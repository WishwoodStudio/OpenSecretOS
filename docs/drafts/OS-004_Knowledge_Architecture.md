# Open Secret OS --- Knowledge Architecture

**Status:** Draft v0.1

## Purpose

Define how knowledge is organized, promoted and consumed.

Knowledge is divided into four classes.

## Layer 1 --- Canonical

Defines project behavior.

Examples:

-   Constitution
-   Decision Log
-   Production Playbook
-   Visual Identity
-   Mechanism Ladder

Only canonical documents may define rules.

------------------------------------------------------------------------

## Layer 2 --- Operational

Supports active production.

Examples:

-   Episode Workspaces
-   Production Packages
-   Research
-   QA

Operational documents never redefine canonical behavior.

------------------------------------------------------------------------

## Layer 3 --- Reference

Reusable but non-authoritative.

Examples:

-   External research
-   Competitor analysis
-   AI experiments
-   Templates

Reference documents may inform decisions but never override Canonical.

------------------------------------------------------------------------

## Layer 4 --- Archive

Historical record only.

Never loaded automatically.

Used only when explicitly requested.

------------------------------------------------------------------------

## Promotion Rules

Reference → Operational → Canonical

Promotion requires production evidence.

Ideas are never promoted directly into Canonical.
